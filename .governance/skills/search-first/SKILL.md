# Search first

Search the relevant code, tests, and installed dependencies within the task's scope. If an established pattern meets the need, reuse it and stop searching. Extend it only where the new requirement differs.

Research external packages or documentation when a real capability gap remains. Before adopting a dependency, check compatibility, maintenance, licence, security, and ongoing cost at a depth proportionate to its role. A search result does not authorize installation, provider use, or an architecture change outside the accepted design.

Use the repository's available search tools. Treat an index as a locator: verify important findings in the current checkout, particularly after a branch or source change. Record only a material decision and its reason; routine reuse needs no research report.
