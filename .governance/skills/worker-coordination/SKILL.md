# Worker Coordination

Read [worker configuration and authority](../../docs/workers.md) and applicable full [principle leaves](../../principles.md). Keep architecture, ambiguous/security/credential/concurrency work, production operations and final review/integration on the existing lead. Use only tools/delegate-worker for bounded straightforward implementation, tests, repetitive edits and isolated fixes. No native or recursive development fan-out.

Record original intent, source, criterion IDs/outcomes/methods and explicit globs before assignment. One writer owns each worktree; overlapping scopes or pending patches are serial. Defaults disabled, capacity 2; changing capacity cannot authorize dispatch. Prepare actual task-bound authority/activation only after the user's scoped approval. Inspect the shared pool and all old runners/receipts. Unknown termination or unreconciled patches block dispatch; never reclaim by PID/age or delete evidence.

The existing runner reserves capacity, binds native ownership, isolates source and returns a patch. Review the full patch, explicitly apply/reject, then independently test every criterion and assess intent. Wrapper exit 0 means unverified patch only. Permit two corrected attempts after initial failure (attempts 2 and 3), with concrete defect evidence and reconciled predecessors inside approved call/time limits. After the third failure, the lead solves it. No automatic retries, criterion weakening or merge.

Use compact source-bound review context and report all measured attempt tokens/cost, marking unknowns unknown. Routine lead review uses the user's selected model at medium reasoning/low verbosity; high needs a concrete reason. No review token/dollar admission gate. Preserve current Desktop model/authentication.
