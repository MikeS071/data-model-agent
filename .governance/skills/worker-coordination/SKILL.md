# Worker Coordination

Read [worker configuration and authority](../../docs/workers.md) and applicable full [principle leaves](../../principles.md). Delegate well-defined work within accepted scope using available native agents or the optional external patch runner. Give one writer ownership of each file set. Keep architecture choices, material ambiguity, credentials, production operations and final review/integration on the lead.

Record original intent, source, criterion IDs/outcomes/methods and explicit globs before an external assignment. The external runner defaults to disabled, with capacity two when activated; changing capacity cannot authorize dispatch. Prepare task-bound authority and activation only after the user's scoped approval. Inspect the shared pool and old receipts. Unknown termination or unreconciled patches block conflicting dispatch; never reclaim by PID or age.

The external runner reserves capacity, binds native ownership, isolates source and returns a patch. Review the full patch, explicitly apply/reject, then independently test every criterion and assess intent. Wrapper exit 0 means unverified patch only. Permit up to three corrected attempts after initial failure (attempts 2 through 4), with concrete defect evidence and reconciled predecessors inside approved call/time limits. The task ID and worker ref retain their retry sequence across scope revisions; after attempt 4 fails, the lead takes over. No automatic retries, criterion weakening or merge.

Use compact source-bound review context and report measured attempt tokens/cost, marking unknowns unknown. Medium reasoning and low verbosity are defaults, not restrictions; use the configured review settings and explain material escalations in the review record. No review token/dollar admission gate. Preserve current Desktop model/authentication.
