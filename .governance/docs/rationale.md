# Rationale and attribution

Reuse the existing proven contracts, action receipts, native worker lifecycle and
source-bound review instead of adding a second runner or orchestration service.
Project adapters own repository identity, branches, standards and real verification.
Portable defaults never claim a project's application journeys are proven.

The 23 conditional principles retain locally adapted material Copyright 2026 Lauren Tan
under the retained [MIT licence](../LICENSE.third-party). No other third-party material is
included under that notice. Project-authored code remains private pending separate
publication/licensing approval.

The `*-provenance.json` files identify reused source blobs and local adaptations. Those
records are historical traceability, not proof of a new project's correctness or
whole-workflow cost savings. No application source, private issue content or Git history
is bundled. Keep one authoritative portable core after publication; project changes travel
through pinned release/upgrade reviews rather than independently maintained copies.
